# Durable Ollama adapter

This standalone MIT-licensed crate is an explicitly opt-in `ProviderAdapter`.
Add it as a path dependency, construct `OllamaAdapter::new("http://127.0.0.1:11434")`, install it with `Harness::install_provider_adapter(Arc::new(adapter))`, and opt a conversation in with `select_provider_adapter(id, true)`. Reopening a selected conversation requires installing the same adapter identity before recovery; see the durable runtime README for scheduler setup. Nothing registers it automatically. Build and test independently with `cargo test --manifest-path crates/durable-ollama/Cargo.toml`.

The adapter prepares OpenAI-compatible chat-completions JSON, allows selected durable hooks to replace it, validates the replacement, and sends that value to `/v1/chat/completions`. Its encoder and SSE decoder adapt code in `crates/ollama/src/lib.rs` under the repository's MIT license. This is the protocol used by the existing Ollama provider and by [upstream pi's Ollama configuration](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/models.md), not native `/api/chat` NDJSON.

Only numeric loopback HTTP origins are accepted; proxies and redirects are disabled, and no credentials are sent. Validation fixes model, streaming, tool definitions, and the maximum output-token field, and bounds the body to 4 MiB. Hooks are trusted: message contents and other request fields may be changed, and validation is not a general authorization or total resource-budget policy for arbitrary Ollama-compatible servers. The host must control hook installation and the local service. Cancellation drops the opening future or stream; it does not prove the server stopped generation.

Legacy function definitions and alternate output-token limit fields are rejected, and `n` may only be 1. When usage is reported, both input and output counts must be present. Completed tool calls must include unique IDs, names, and an arguments field; malformed argument JSON remains available to the runtime for its normal tool-error handling.

Parity is intentionally partial: there is no native Ollama NDJSON, authentication, remote endpoint, provider compatibility settings, sampling configuration API, replay of reasoning details, cache retention/accounting, model discovery/loading progress, or finish-reason inference. Reasoning text and basic usage are returned, but provider replay and detailed accounting are not. Tool results and user images use the existing provider's OpenAI-compatible encoding. A successful completion requires a finish reason and `[DONE]`; malformed, truncated, or error streams fail. This implementation is independent and may drift from the ordinary provider.
