# Pi と Rust Harness の拡張比較

PLT-6369、PLT-6388。初回の3課題に、コード修正、模擬書込み、長い会話の圧縮、分岐レビューを加えた。前回の3課題の結果は固定した初期実装のベースラインとして保存している。 [初期ベースライン](evaluation.md)

## 条件と判定

Pi v1.5.0 `f9a26365568127461c47a07a37dcb42c140a3ac5`、Ollama v0.40.15、Qwen2.5 7B Q4_K_M。同一 Apple M5 Pro の1台で、4096コンテキスト、並列度1、温度0、seed 123、各要求512出力トークン、試行全体で最大6要求と60秒を共通にした。3反復で実行順を交互に変更した。モデルをウォームアップし、Ollama が報告したキャッシュヒット数を記録した。各試行に新しいセッションを用意した。

全21組で最初のプロンプトとツール定義が一致した。単一タスクの15組は後続文脈も一致した。圧縮とレビューでは、両ハーネスの要約指示、保持範囲、分岐方法、レビュー時に見せるツールが異なる。Pi は SDK の履歴ツリー、Rust は読取り専用の子セッションを使った。処理時間や使用量の差にはこの構成差が含まれる。

判定は回答文字列と必要なツール結果を独立に確認した。コード修正は変更後の合成コードを既知の式に限定して実行し、2つの入力で割引を検証した。模擬書込みは注文 QO-19 の効果が1回だけ記録されたことを確かめた。すべて隔離された合成データを使った。 [評価コード](../evaluation/compare.mjs)

## 実測

| 課題 | Rust / Pi の成功 | 時間中央値 Rust / Pi（ms） | 入力・出力トークン中央値 Rust / Pi |
| --- | ---: | ---: | ---: |
| 読取り | 3/3 / 3/3 | 798 / 1401 | 549・27 / 549・27 |
| 固定コマンド | 3/3 / 3/3 | 617 / 999 | 547・23 / 547・23 |
| 複数ツール＋業務API | 0/3 / 0/3 | 1298 / 1681 | 623・58 / 623・58 |
| コード修正 | 3/3 / 3/3 | 1419 / 1889 | 816・59 / 816・59 |
| 模擬業務書込み | 3/3 / 3/3 | 816 / 1058 | 750・28 / 750・28 |
| 圧縮後の継続 | 3/3 / 3/3 | 2788 / 6006 | 5103・109 / 5483・247 |
| 分岐レビュー | 0/3 / 0/3 | 6039 / 5791 | 1728・271 / 2407・242 |

両者とも **15/21件成功**。複数ツール課題では正しい値を取得した後、指定外の区切り方で回答した。分岐レビューでは正しい権限に言及した回答もあったが、どちらも全試行で厳密な回答形式を満たさなかった。Rust のレビューでは資料に存在しないファイルや注文を参照した試行があった。モデルの出力品質として記録し、分岐が正しい文脈を選択したことは別の決定的テストで検証した。

キャッシュ読取りの累計は Rust 26,028 トークン、Pi 28,057 トークン。比較表には失敗タスクも含めた。ローカルモデルの API 従量費は成功・失敗とも $0、人の介入は両者とも0回。電力、機材、実運用の課金は計測対象外。 [全試行と失敗分類](../evaluation/expanded-results.json)

圧縮課題は Rust が少ないトークンで、両者とも記録した検証コードを復元した。レビューの品質はこの条件ではいずれも不足している。少数の合成課題からモデルやハーネス全般の品質差は推定できない。

## 拡張追加と復帰

AI が `pi-rs-fixture-tools` を独立crateとして追加し、合成のコード修正と注文の操作、版付きの実行回数を実装した。ホストの機能指定で組み込む。評価用の拡張を有効にするコード変更はワークベンチの合成部に閉じている。 [サンプル拡張](../crates/fixture-tools/src/lib.rs)

拡張の候補を別バイナリへビルドして検証し、元セッションを開いた。試験では同じ検証コードを復元し、未対応の状態版は診断とともに拒否した。前のバイナリと設定に戻すと拡張状態は履歴に残り、模擬書込みは1件のままだった。Pi は比較スクリプトで SDK にインラインの評価ツールを登録し、追加ビルドは0回。Rust の計測は候補のビルド開始から利用までで、ソース執筆とレビュー時間は含まない。 [拡張の検証結果](../evaluation/extension-cycle-results.json)

## 再現

```sh
npm ci --ignore-scripts --prefix evaluation
cargo build --locked --release -p pi-rs-workbench --features evaluation-fixtures
node evaluation/compare.mjs
node evaluation/extension-cycle.mjs
```

`OLLAMA_URL` と `PI_RS_BIN` で検証先を変更できる。`EVAL_TRACE_DIR` には合成データのリクエスト本文を保存する。モデルダイジェストと設定は結果JSONに保存する。
