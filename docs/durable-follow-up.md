# Durable の機能優先順位と残りタスク

初回統合の [PR #723](https://github.com/quantum-box/pi-rs/pull/723) は `main`（`872aea19e`）にマージ済み。この一覧は、利用時の影響と機能間の依存関係で順序をつけたもの。

## 実装の優先順位

| 順位 | 領域 | 作業と完了条件 |
| --- | --- | --- |
| 1 | チェックポイント対応ツールの途中出力 | 今回の実装で、テキストの追記、会話と個別タスクのライブ表示、出力を省略した成功時のテキスト・詳細の引き継ぎに対応。ツールごとに保持するバイト数・行数と先頭／末尾を指定できる。成功結果への途中診断の統合と履歴ストリームへの出力記録は後続。 |
| 2 | 子ツール・サブエージェント | 上流と同じ並列呼び出し・待機・所有関係を整える。再起動で子を二重実行せず、子の完了通知と親の中止を再現できることを確認する。 |
| 3 | セッション操作 | エントリ編集、複数操作を一度に確定するトランザクション、文書ドラフトを整える。途中で失敗しても一部の変更だけが残らないことを検証する。 |
| 4 | 履歴・フォーク | 任意のエントリIDからのフォークと、操作単位の履歴監視を追加する。再起動後もフォーク位置と操作順を再現できることを確認する。 |
| 5 | 既存CLI・TUI・RPCとの統合 | Durable を選べる入口と組み込みプロバイダー連携を設計する。既存セッション経由の影響を確認し、Durable の結果と進捗を利用画面で見られることを確認する。 |
| 6 | 履歴の回収 | 保存期限と回収対象を定義し、参照中の履歴やフォークが保持されることを確認する。 |

途中出力の API と現在の制限は[キャンセル設計書](durable-conversation-cancel-design.md)を参照。その他の詳細は[上流互換性の一覧](pi-durable-parity.md)と[Durable の設計](pi-durable-design.md)を参照。

## 運用・検証

### マージ後のCI確認

- [マージ後の Rust parity](https://github.com/quantum-box/pi-rs/actions/runs/45543611515) では、確認時点で Windows は成功、Linux は実行中。macOS では書き込み競合のテスト `unsafe_initial_memo_busy_retries_without_dispatching_early` が失敗した。Durable の実行テストは Linux・macOS で行う。[macOS ジョブ](https://github.com/quantum-box/pi-rs/actions/runs/45543611515/job/138967939053)
- 失敗時はジョブログを確認し、機能の回帰、テストの競合、実行時間上限のどれに当たるかを切り分ける。修正が必要なら該当ケースを再現し、修正後に対象ジョブを再実行する。
- **完了条件**　マージ後の対象ジョブが成功し、結果を実行履歴から確認できる。

### 実験機能の既定化判断

`experimental-graph-scope` と `experimental-graph-revision` は明示的に有効化する。合成負荷では、4,096ルートで無関係な書き込みの p95 が約45 ms、8,192ルートでは40回すべてで走査上限に達した。測定条件と現在の上限は[キャンセル設計書](durable-conversation-cancel-design.md)を参照。

- 実運用を代表するDBのコピーで、旧版から v4 への移行、再オープン、バックアップ復元を検証する。旧バイナリでの書き込み拒否と、復元時にバックアップ後の書き込みが失われる範囲も確認する。
- 代表的なグラフ規模と更新頻度で、書き込み遅延、走査上限への到達率、手動照合が必要になった件数を測る。許容値を決め、超過時の運用手順を残す。
- **完了条件**　移行・復元の手順と測定結果から、既定化するか、明示有効化を継続するかを判断し、根拠を設計書に記録する。
