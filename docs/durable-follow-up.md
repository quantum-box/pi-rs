# Durable の機能優先順位と残りタスク

初回統合の [PR #723](https://github.com/quantum-box/pi-rs/pull/723) は `main`（`872aea19e`）にマージ済み。この一覧は、利用時の影響と機能間の依存関係で順序をつけたもの。[PR #730](https://github.com/quantum-box/pi-rs/pull/730) に途中出力の基礎、[PR #731](https://github.com/quantum-box/pi-rs/pull/731) に各領域の追加実装をまとめている。

## 実装の優先順位

| 順位 | 領域 | 作業と完了条件 |
| --- | --- | --- |
| 1 | チェックポイント対応ツールの途中出力 | 今回の実装で、テキストの追記、会話と個別タスクのライブ表示、出力を省略した成功時のテキスト・詳細の引き継ぎに対応。ツールごとに保持するバイト数・行数と先頭／末尾を指定できる。会話に属する親と子の確定済み途中出力も履歴ストリームで読める。会話のルートツールはフックなしの成功時に途中診断も引き継ぐ。フックを使う場合の診断統合は後続。 |
| 2 | 子ツール・サブエージェント | リプレイ可能な親は、実行中に登録済みの子を開始し、期限付きで結果を待てる。子の再接続は明示したキーによる。リプレイ不可の子が中断された場合は照合が必要になり、自動再実行を行わない。リプレイ不可の親、汎用ツール、サブエージェントへの統合は後続。 |
| 3 | セッション操作 | 会話のトランザクション内で JSON 文書ドラフトとフォーク時の文書方針を編集し、エントリや通知とまとめて保存できる。上流と同じく、履歴へのエントリ追加を基本とする。残りは上流のエントリツリー、型付き文書とライフサイクル、操作の組み合わせの拡張。 |
| 4 | 履歴・フォーク | 履歴は保存したカーソルから再開でき、以後の会話とアプリケーション履歴の更新を確定順に読み出せる。フォーク先で追加した表示エントリも位置指定に使える。残りは継承した表示エントリ自体など、未対応の位置指定と、個々の操作を統合した監視。 |
| 5 | 既存CLI・TUI・RPCとの統合 | 独立した実験用 CLI で OpenAI Responses のテキスト会話を開始・再開できる。JSON モードで確定済みの途中出力を表示する。既存 CLI からは `--durable` で起動できる。TUI と既存 RPC への統合は後続。 |
| 6 | 履歴の回収 | 終了したチェックポイント対応ツールの作業用途中出力を、タスク指定で回収できる。保存期限の自動適用と、履歴・フォーク本体の参照関係を踏まえた回収は後続。 |

途中出力の API と現在の制限は[キャンセル設計書](durable-conversation-cancel-design.md)を参照。その他の詳細は[上流互換性の一覧](pi-durable-parity.md)と[Durable の設計](pi-durable-design.md)を参照。

## 実験用テキスト CLI

`OPENAI_API_KEY` を環境に設定してから、SQLite ファイル、Responses の送信先、モデルを指定する。 `pi-rs-durable` を `pi-rs` と同じディレクトリにインストールしている場合は、下の `cargo run … --` を `pi-rs --durable` に置き換えられる。

```sh
cargo run -p pi-rs-durable --features text-cli --bin pi-rs-durable -- \
  --db durable.sqlite --endpoint https://api.openai.com/v1/responses \
  --model MODEL --json '最初のメッセージ'
```

続けるには、同じデータベースと送信先を指定し、`--model MODEL` を最初に表示された `--conversation UUID` に置き換える。同じ入力を再送する場合は同じ `--request-id` を使う。`--json` は会話 ID、保存済みのテキスト進捗、確定結果を1行ずつ出力する。

## 運用・検証

### マージ後のCI確認

- 初回マージ後の検証は Windows が成功、macOS が失敗、Linux が取り消しになった。[実行結果](https://github.com/quantum-box/pi-rs/actions/runs/45543611515)
- PR #730 の再検証では Linux と Windows が成功。macOS の競合テストは、SQLite が競合を返す前に固定時間でロックを解放していた。ロック解放を競合の通知に合わせ、ローカルで対象テスト群35件の成功を確認した。[修正前の macOS ジョブ](https://github.com/quantum-box/pi-rs/actions/runs/45551181860/job/138992569329)
- **完了条件**　マージ後の対象ジョブが成功し、結果を実行履歴から確認できる。

### 実験機能の既定化判断

`experimental-graph-scope` と `experimental-graph-revision` は明示的に有効化する。合成負荷では、4,096ルートで無関係な書き込みの p95 が約45 ms、8,192ルートでは40回すべてで走査上限に達した。測定条件と現在の上限は[キャンセル設計書](durable-conversation-cancel-design.md)を参照。

- 実運用を代表するDBのコピーで、旧版から v4 への移行、再オープン、バックアップ復元を検証する。旧バイナリでの書き込み拒否と、復元時にバックアップ後の書き込みが失われる範囲も確認する。
- 代表的なグラフ規模と更新頻度で、書き込み遅延、走査上限への到達率、手動照合が必要になった件数を測る。許容値を決め、超過時の運用手順を残す。
- **完了条件**　移行・復元の手順と測定結果から、既定化するか、明示有効化を継続するかを判断し、根拠を設計書に記録する。
