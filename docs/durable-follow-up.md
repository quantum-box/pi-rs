# Durable の機能優先順位と残りタスク

初回統合の [PR #723](https://github.com/quantum-box/pi-rs/pull/723) に続き、途中出力の基礎を [PR #730](https://github.com/quantum-box/pi-rs/pull/730)、子ツール・文書・履歴・テキストCLIの拡張を [PR #731](https://github.com/quantum-box/pi-rs/pull/731)、テキストRPCを [PR #732](https://github.com/quantum-box/pi-rs/pull/732) で `main` に取り込んだ。この一覧は、利用時の影響と機能間の依存関係で順序をつけたもの。

## 実装の優先順位

| 順位 | 領域 | 作業と完了条件 |
| --- | --- | --- |
| 1 | チェックポイント対応ツールの途中出力 | 今回の実装で、テキストの追記、会話と個別タスクのライブ表示、出力を省略した成功時のテキスト・詳細の引き継ぎに対応。ツールごとに保持するバイト数・行数と先頭／末尾を指定できる。会話に属する親と子の確定済み途中出力も履歴ストリームで読める。成功時は、選択済みの終了フックにも途中診断を引き継ぎ、フック後の結果に保存する。フックなしの会話ルートでも途中診断を確定結果に保存する。 |
| 2 | 子ツール・サブエージェント | 会話内の親は、実行中に登録済みのチェックポイント対応の子を開始し、期限付きで結果を待てる。リプレイ不可の親が中断された場合、その実行中に起動した未完了の子は自動で再開しない。子の再接続は明示したキーによる。リプレイ不可の子が中断された場合は照合が必要になり、自動再実行を行わない。フックを選択していない親は、リプレイ可能な汎用タスクツールも呼び出せる。通常の非同期ツールも、リプレイ方針を明示して子として登録できる。途中出力のテキストと詳細を保存し、確定結果はツールの返り値を使う。通常ツールからも、登録済みの子を順序付きで呼び出せる。リプレイ可能な親は、前景サブエージェントを起動して、その応答を待てる。再起動後は同じ会話と入力を使う。UI・拡張状態との連携は後続。 |
| 3 | セッション操作 | 会話のトランザクション内で JSON または Rust の型で編集できる文書ドラフトとフォーク時の文書方針を編集し、エントリや通知とまとめて保存できる。上流と同じく、履歴へのエントリ追加を基本とする。定義付きの会話文書は、スキーマ版とフォーク方針を固定し、移行・終了・再作成を同じトランザクション内で扱える。タスク文書にも型とスキーマ版を定義できる。移行は文書の ID を保ち、削除後の再作成には新しい ID を付ける。タスク自体が終了すると文書は削除され、監視も終了する。新規フォークは直接の親と分岐位置を子の作成時に記録する。新規フォークの親をたどって、圧縮やリセット前のメッセージを元の ID で一覧できる。セッション名の変更はメッセージと同じ履歴カーソルで読み出せ、継承した変更時点からもフォークできる。履歴の表示可能なエントリにはラベルを付けられる。フォークでは分岐先に残るエントリの最新のラベルと消去を引き継ぐ。拡張機能などが追加した表示専用のカスタムエントリも、元の ID で履歴を読み、ラベルを付け、分岐位置に使える。SDK では、保存済みカーソルから親 ID・ラベル・現在位置付きのエントリツリーを読める。残りは同じセッション内での分岐の切り替え、TUI・RPC のツリー表示、他のエントリ種別・コンテキスト編集の拡張、保存方式と操作の組み合わせの拡張。 |
| 4 | 履歴・フォーク | 履歴は保存したカーソルから再開でき、会話の状態、アプリケーション履歴、モデル・ツールの途中出力、会話のアドレス範囲にある文書の操作と削除を同じカーソルで確定順に読み出せる。フォーク先で追加した表示エントリと、作成時の由来を検証できる継承エントリを位置指定に使える。残りは未対応の位置指定と、会話のアドレス範囲外にあるタスク文書の監視。 |
| 5 | 既存CLI・TUI・RPCとの統合 | 独立した実験用 CLI で OpenAI Responses のテキスト会話を開始・再開できる。JSON モードで確定済みの途中出力を表示する。既存 CLI からは `--durable` で起動できる。テキスト RPC では入力、ストリーミング、中止、状態とメッセージの取得に対応。実行中に追加入力を永続キューに登録でき、キューの一括取り消しと配信モード設定にも対応。OpenAI Responses では画像付き入力を保存し、再開後の履歴にも画像を返せる。既存 TUI の描画とエディターを使う実験モードで、入力、応答のライブ表示、履歴再開と画像の扱いに対応。ツール・拡張を含む通常 TUI の操作と、待機中のキュー投入は後続。 |
| 6 | 履歴の回収 | 終了したツールの作業用途中出力は、タスク指定またはスケジューラーの保存期間設定で回収できる。自動回収は終了状態を確認してから保存期間を数え、確認結果は再起動後も保持する。公開済みの途中出力、結果、フォークは引き続き読める。残りは履歴・フォーク本体の参照関係を踏まえた回収。 |

途中出力の API と現在の制限は[キャンセル設計書](durable-conversation-cancel-design.md)を参照。その他の詳細は[上流互換性の一覧](pi-durable-parity.md)と[Durable の設計](pi-durable-design.md)を参照。

## 実験用テキスト CLI

`OPENAI_API_KEY` を環境に設定してから、SQLite ファイル、Responses の送信先、モデルを指定する。 `pi-rs-durable` を `pi-rs` と同じディレクトリにインストールしている場合は、下の `cargo run … --` を `pi-rs --durable` に置き換えられる。

```sh
cargo run -p pi-rs-durable --features text-cli --bin pi-rs-durable -- \
  --db durable.sqlite --endpoint https://api.openai.com/v1/responses \
  --model MODEL --json '最初のメッセージ'
```

続けるには、同じデータベースと送信先を指定し、`--model MODEL` を最初に表示された `--conversation UUID` に置き換える。同じ入力を再送する場合は同じ `--request-id` を使う。`--json` は会話 ID、保存済みのテキスト進捗、確定結果を1行ずつ出力する。

テキスト RPC は `--json` とコマンド末尾のメッセージを `--rpc` に置き換えて起動する。標準入力から1行ごとに `prompt`、`abort`、`get_state`、`get_messages` を受け取る。`set_session_name` は表示名を履歴に追記し、`get_state` の `sessionName` で確認できる。HTTPS または数値ループバックの HTTP で OpenAI Responses に接続する場合は、`prompt`、`steer`、`follow_up` の `images` に `type: "image"`、`mimeType`、base64 の `data` を持つ画像を追加できる。画像は送信するモデル向けに調整した状態で保存する。実行中は `steer`、`follow_up`、または `streamingBehavior` 付きの `prompt` で追加入力を積む。`clear_queue` は未処理の入力をまとめて取り消し、種別ごとのテキストを返す。確定した途中出力は `message_update` イベントで返す。生成を再試行した場合は別のアシスタントメッセージを開始し、失敗時はその試行で保存した途中出力を返す。`abort` は実行中のターンが終了してから応答する。残っているキューは次の入力が来るまで保存する。

## 実験用 Durable TUI

`pi` と `pi-rs-durable` を同じディレクトリにインストールしてから起動する。

```sh
pi --durable --tui --db durable.sqlite \
  --endpoint https://api.openai.com/v1/responses --model MODEL
```

画面のセッション ID を控え、再開時は `--model MODEL` を `--conversation UUID` に置き換える。通常の TUI と同じテーマ、入力欄、キーバインドを使う。生成中の入力はステアリングまたはフォローアップとしてキューに入り、中止時は未処理の入力と画像を編集欄に戻す。会話は指定した SQLite に保存する。

## 運用・検証

### マージ後のCI確認

- 強制終了後の復旧テストの競合を [PR #734](https://github.com/quantum-box/pi-rs/pull/734) で修正して `main` に取り込んだ。対象 PR は Linux、macOS、Windows の [ネイティブ CI](https://github.com/quantum-box/pi-rs/actions/runs/45651834900) を通過した。

- 初回マージ後の検証は Windows が成功、macOS が失敗、Linux が取り消しになった。[実行結果](https://github.com/quantum-box/pi-rs/actions/runs/45543611515)
- PR #730 の再検証では Linux と Windows が成功。macOS の競合テストは、SQLite が競合を返す前に固定時間でロックを解放していた。ロック解放を競合の通知に合わせ、ローカルで対象テスト群35件の成功を確認した。[修正前の macOS ジョブ](https://github.com/quantum-box/pi-rs/actions/runs/45551181860/job/138992569329)
- **完了条件**　マージ後の対象ジョブが成功し、結果を実行履歴から確認できる。

### 実験機能の既定化判断

`experimental-graph-scope` と `experimental-graph-revision` は明示的な有効化を継続する。走査上限に達する負荷があり、v4 から標準ビルドに戻るには移行前のバックアップが必要になる。合成負荷では、4,096ルートで無関係な書き込みの p95 が約45 ms、8,192ルートでは40回すべてで走査上限に達した。測定条件と現在の上限は[キャンセル設計書](durable-conversation-cancel-design.md)を参照。

- 会話、親子タスク、文書を含む256件の合成レコードで、v3 から v4 への移行、再オープン、旧書き込み接続の拒否、バックアップ復元を検証した。復元先にはバックアップ以降の書き込みが含まれないことも確認した。実運用を代表するDBのコピーで、同じ手順と復旧時間を検証する。
- 代表的なグラフ規模と更新頻度で、書き込み遅延、走査上限への到達率、手動照合が必要になった件数を測る。許容値を決め、超過時の運用手順を残す。
- **完了条件**　移行・復元の手順と測定結果から、既定化するか、明示有効化を継続するかを判断し、根拠を設計書に記録する。
